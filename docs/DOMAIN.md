# 업무 배경

> 사용자가 알려준 실무 이야기를 모아둔다. 코드에도 git log 에도 안 남는,
> **직접 듣지 않으면 알 수 없는 것들**이다.
>
> 새로 들은 것이 생기면 그때그때 여기에 붙인다. 미루면 사라진다.

---

## 1. 일이 흘러가는 순서

```text
① 의뢰       지자체가 공문으로 시료 검사를 의뢰한다
② 접수       접수번호가 붙는다.  이게 모든 것의 단위가 된다
③ 시험       항목마다 담당자와 기기가 다르다
④ 입력       종이를 보며 숫자키패드로 시스템에 넣는다    ← 여기서 오타가 난다
⑤ 계산       시스템이 계산식을 적용해 최종값을 만든다
⑥ 기록부     시험기록부를 뽑는다.  입력값과 계산식이 찍혀 나온다
⑦ 검증       기록부와 원자료(종이)를 대조한다            ← 지금의 검수
⑧ 결재       승인
⑨ 성적서     관인 찍힌 최종본이 나온다
⑩ 통보       공문에 성적서를 붙여 의뢰처에 보낸다
```

**검증(⑦)이 입력(④) 뒤에 있다.** 그래서 ⑥⑦이 매번 반복된다.

---

## 2. 값이 어디서 오는가

항목마다 출처가 다르다. 이게 여러 문서를 읽어야 하는 이유다.

```text
pH · DO      현장측정기          인쇄물
BOD · SS     손글씨 검사일지      사람이 적은 종이
TOC          TOC 분석기          인쇄물
T-N · T-P    자동분석기          인쇄물
```

BOD·SS 만 성격이 다르다. **원본이 손글씨**라 판독을 확신할 수 없다.
나머지는 원본이 기계 출력이라 인쇄체다.

---

## 3. 기기 컴퓨터는 격리되어 있다

시험 기기에는 전용 컴퓨터가 붙어 있고, 결과를 화면에 엑셀로 띄운다.
그런데 **인터넷도 USB도 막혀 있어 파일을 꺼낼 수 없다.**

그래서 인쇄한다. 그 종이를 보며 사람이 시스템에 손으로 다시 친다.

```text
완벽한 디지털 데이터  →  종이  →  사람 눈  →  사람 손  →  다시 디지털
                            └── 여기서만 나빠진다 ──┘
```

**이 격리를 우회하려는 시도는 하지 않는다.** 인쇄물을 읽는 것은 우회가 아니다.
이미 정상적으로 반출이 허용된 결과물이다.

---

## 4. 기기 한 번에 여러 의뢰건이 섞인다

기기는 배치로 돌아간다. 한 번 돌릴 때 여러 접수번호의 시료가 같이 들어간다.

```text
자동분석기 출력 한 장
  ├ 표준품 · 세척수 · 블랭크        품질관리용
  ├ A 지역 시료                    다른 접수번호
  ├ B 습지 유입 / 유출              이번 건
  └ C 지역 시료                    또 다른 접수번호
```

그래서 **필요한 시료만 골라내는 것**이 필수 기능이다.
전체를 다 읽어서 뿌리면 안 되고, 찾을 이름을 미리 알려주고 그것만 찾는다.

반대로 말하면, 기기 출력물은 **한 번 읽어서 사전을 만들어두고
여러 접수번호가 조회하는** 구조가 맞다. 뭉치마다 다시 읽을 필요가 없다.

---

## 5. 검증이란 무엇을 보는 일인가

용어부터 맞춰둔다.

```text
원자료   기기 출력물 · BOD/SS 수기 일지.  종이 그 자체
```

연구사는 이 종이를 보며 숫자키패드를 두드려 시스템에 넣는다.
**두드리다 틀렸을 수 있으니 나중에 다시 본다.** 그게 지금의 검증이다.

```text
종이  ↔  사람이 시스템에 친 값
         검증 대상은 "사람의 손"
```

시점은 입력이 끝난 뒤다. 시험기록부를 뽑아 종이와 나란히 놓고,
형광펜으로 이번 건 시료를 칠해가며 눈으로 대조한다.

유입과 유출이 연달아 나오는데 두 번째 줄은 지명이 생략되어 있어서,
형광펜은 짝을 놓치지 않으려는 표시이기도 하다.

---

## 6. 그래서 이 도구는 검증을 앞으로 당긴다

없애는 것이 아니라 **대상과 시점을 바꾼다.**

```text
지금     종이  ↔  사람이 친 값
         언제  입력 다 하고, 기록부 뽑아서
         무엇  사람의 오타

바뀌면   종이  ↔  도구가 읽은 값
         언제  입력하기 전, 화면에서
         무엇  도구의 오독
```

확인이 끝나면 복붙으로 넣는다. **복붙은 값을 틀리지 않으므로
"제대로 들어갔는가"를 물을 필요가 없어진다.**

```text
사람이 친다   →  틀릴 수 있다  →  나중에 확인해야 한다
복붙한다      →  안 틀린다     →  확인할 게 없다
```

확인도 훨씬 싸진다. 종이와 시스템 화면을 번갈아 보며 전부 훑는 대신,
한 화면에서 의심스러운 몇 칸만 본다. 품질관리 시료가 정렬을 스스로
검증해주므로 사람이 볼 것이 두세 칸으로 준다.

### 다만 복붙도 밀릴 수 있다

값 자체는 안 틀리지만 **붙는 위치가 밀리면** 전부 엉뚱한 칸에 들어간다.
값이 다 정상 범위라 사람 눈에 안 걸린다.

```text
초기 몇 달   복붙 후에도 기록부를 뽑아 대조한다.  자동이라 부담 없음
확인된 뒤    사후 대조를 줄인다
```

데이터 책임은 연구사에게 있다. "도구가 읽었으니 맞겠지"로 넘어가면 안 된다.
**검증을 없애는 것이 아니라 기계가 대신하는 것**으로 설명해야 도입도 쉽다.

## 7. 입력 전에는 무엇으로 검증하나

기록부도 성적서도 아직 없다. 대조할 상대가 없으므로 **스스로 확인**한다.
재료는 문서 안에 이미 들어 있다.

```text
① 품질관리 시료    표준품 행의 Ref./Target 열에 정답이 인쇄되어 있다
                  세척수 · 바탕시료는 0 근처, 표준품은 알려진 농도 근처
                  → 판독과 정렬이 맞는지 스스로 판정

② 이중 판독       같은 파일을 두 번 읽어 대조

③ 개수 확인       시료명 개수 = 값 개수 = 이번 건 시료 수

④ 계산해보기      원자료로 최종값을 계산해 상식 범위인지 본다
                  이건 검증용이지 입력용이 아니다
```

---

## 8. 시스템 입력 화면과 붙여넣기

화면이 두 종류다.

```text
계산식 있는 화면    변수 여러 개를 넣으면 계산되어 최종값이 나온다
                   BOD · SS · TOC
계산식 없는 화면    값 하나만 넣는다
                   T-N · T-P · pH · DO
```

**입력 칸이 엑셀처럼 되어 있어 붙여넣기가 된다.** 단위는 시료 하나다.

```text
시료 하나  =  한 행
열 순서    =  화면의 입력 칸 순서
```

그래서 내보내기는 시료별 한 행짜리 표가 된다.
**열 순서는 아직 확인하지 못했다.** 설정 파일로 빼두고 나중에 채운다.

---

## 9. 시험기록부는 입력의 결과물이다

입력 자료가 아니라 **입력이 끝나야 나오는 산출물**이다.
원자료를 넣으면 시스템이 계산식을 적용해 최종값을 만들고,
그 계산 과정이 기록부에 그대로 찍힌다.

```text
BOD : (8.84 - 7.67) * (300/300) * 1 = 1.17
SS  : (96.45 - 93.69) * 1000/1000 * 1 = 2.76
T-N : 2.0854 * 1 = 2.0854
TOC : (2.55 - 0) * 1 = 2.55
```

그러니 **도구가 시스템에 넘길 것은 괄호 안의 숫자들**이다.
계산은 시스템이 한다. 도구가 계산해보는 것은 검증 목적일 뿐이다.

---

## 10. 검량선은 입력 대상이 아니다

뭉치에 검량선 출력물이 여러 장 들어 있는데, 이건 **품질 기록**이다.
기기가 제대로 보정되었는지를 남기는 것이지 시스템에 입력하는 값이 아니다.

판별기가 이걸 알아보고 **넘기는 것**도 일이다.

## 11. 용어

```text
원자료       기기 출력물 · 수기 일지.  종이 그 자체를 가리킨다
접수번호     의뢰 한 건에 붙는 번호.  모든 것의 단위
시료         검사할 물 한 병.  접수번호 하나에 여러 개가 붙는다
검체         시료와 같은 말.  시스템 화면에서 이 말을 쓴다
성적서       최종 결과 문서.  값이 반올림되어 있다.  결재 후에 나온다
시험기록부    입력값과 계산식이 그대로 찍힌 문서.  입력 후에 나온다
배치         기기를 한 번 돌릴 때 함께 넣는 시료 묶음
검량선       기기가 신호를 농도로 바꾸는 기준선.  품질 기록용
표준품       농도를 아는 시료.  기기가 맞는지 확인하려고 같이 넣는다
블랭크       아무것도 없는 시료.  0 이 나와야 한다
```
