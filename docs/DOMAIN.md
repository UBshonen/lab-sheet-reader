# 업무 배경

> 사용자가 알려준 실무 이야기를 모아둔다. 코드에도 git log 에도 안 남는,
> **직접 듣지 않으면 알 수 없는 것들**이다.
>
> 새로 들은 것이 생기면 그때그때 여기에 붙인다. 미루면 사라진다.

---

## 1. 일이 흘러가는 순서

```text
① 의뢰       지자체가 공문으로 시료 검사를 의뢰한다
② 접수       접수번호가 붙는다.  이게 모든 것의 단위가 된다
③ 시험       항목마다 담당자와 기기가 다르다
④ 입력       결과를 정보시스템에 입력한다     ← 여기서 오타가 난다
⑤ 결재       승인 요청 → 승인
⑥ 성적서     시스템이 성적서를 출력한다
⑦ 통보       공문에 성적서를 붙여 의뢰처에 보낸다
```

**⑥은 ④가 끝나야 나온다.** 그래서 입력 전에는 성적서로 대조할 수가 없다.
검증을 스스로 해야 하는 이유가 이것이다.

---

## 2. 값이 어디서 오는가

항목마다 출처가 다르다. 이게 이 도구가 여러 문서를 읽어야 하는 이유다.

```text
pH · DO      현장측정기          인쇄물
BOD · SS     손글씨 검사일지      사람이 엑셀에 옮겨 적음
TOC          TOC 분석기          인쇄물
T-N · T-P    자동분석기          인쇄물
```

BOD·SS 만 성격이 다르다. **원본이 손글씨**라 판독을 확신할 수 없다.
나머지는 원본이 기계 출력이라 인쇄체다.

---

## 3. 기기 컴퓨터는 격리되어 있다

시험 기기에는 전용 컴퓨터가 붙어 있고, 결과를 화면에 엑셀로 띄운다.
그런데 **인터넷도 USB도 막혀 있어 파일을 꺼낼 수 없다.**

그래서 인쇄한다. 그 종이를 보며 사람이 정보시스템에 손으로 다시 친다.

```text
완벽한 디지털 데이터  →  종이  →  사람 눈  →  사람 손  →  다시 디지털
                            └── 여기서만 나빠진다 ──┘
```

**이 격리를 우회하려는 시도는 하지 않는다.** 인쇄물을 읽는 것은 우회가 아니다.
이미 정상적으로 반출이 허용된 결과물이다.

---

## 4. 두 가지 입력 방식이 섞여 있다

같은 기관 안에서도 항목에 따라 다르다.

```text
BOD · SS       엑셀에 입력 →  복사 →  시스템에 붙여넣기
T-N · T-P      인쇄물 보고 →  키패드로 직접 입력
```

**시스템은 붙여넣기를 받는다.** BOD·SS 가 그렇게 들어가고 있으니까.
그런데 T-N·T-P 는 붙여넣을 엑셀이 없어서 손으로 친다.

그러니 이 도구가 할 일은 **없는 엑셀을 인쇄물에서 되살리는 것**이다.
그러면 T-N·T-P 도 붙여넣기 경로를 탈 수 있고, 키패드 입력이 사라진다.

---

## 5. 기기 한 번에 여러 의뢰건이 섞인다

기기는 배치로 돌아간다. 한 번 돌릴 때 여러 접수번호의 시료가 같이 들어간다.

```text
자동분석기 출력 한 장
  ├ 표준품 · 세척수 · 블랭크        품질관리용
  ├ A 지역 시료                    다른 접수번호
  ├ B 습지 유입 / 유출              이번 건
  └ C 지역 시료                    또 다른 접수번호
```

그래서 **필요한 시료만 골라내는 것**이 필수 기능이다.
전체를 다 읽어서 뿌리면 안 되고, 찾을 이름을 미리 알려주고 그것만 찾는다.

반대로 말하면, 기기 출력물은 **한 번 읽어서 사전을 만들어두고
여러 접수번호가 조회하는** 구조가 맞다. 뭉치마다 다시 읽을 필요가 없다.

---

## 6. 지금은 형광펜으로 짝을 맞춘다

검수는 이미 하고 있다. 사람이 하고 있을 뿐이다.

```text
기기 출력물에서 이번 건 시료를 형광펜으로 칠한다
그 값을 시스템에 입력된 값과 눈으로 대조한다
```

그러니 이 도구는 **없던 일을 만드는 게 아니라 하던 일을 대신한다.**
도입 저항이 낮은 이유이고, 만들 때도 그 자세를 유지해야 한다.

특히 유입과 유출이 연달아 나오는데 두 번째 줄은 지명이 생략되어 있어서,
형광펜은 짝을 놓치지 않으려는 표시이기도 하다.

---

## 7. 무엇과 무엇을 대조하는가

성적서와 시험기록부는 **시스템이 만들어낸 문서**다. 사람이 입력한 값이
거기 찍혀 나온다. 기기 인쇄물은 원본 값이다.

```text
시스템 산출물                    기기 인쇄물
  성적서 (최종 결과)      ↔        자동분석기 · TOC · 현장측정기
  시험기록부 (원자료+계산식)
```

**이 대조가 지금 실무에서 하고 있는 검증이다.**

시험기록부에는 원자료와 계산식과 결과가 한 줄에 다 찍힌다.

```text
BOD : (8.84-7.67)*(300/300)*1 = 1.17
SS  : (96.45-93.69)*1000/1000*1 = 2.76
T-N : 2.0854*1 = 2.0854
TOC : (2.55-0)*1 = 2.55
```

그래서 검증이 세 겹으로 걸린다.

```text
① 기기값  ↔  기록부 원자료        사람의 입력 오타를 잡는다
② 계산식을 다시 계산  ↔  결과값    문서 안에서 스스로 맞는지 본다
③ 결과값을 반올림  ↔  성적서 값    시스템 계산이 예상대로인지 본다
```

②가 특히 쓸모 있다. **판독이 틀리면 계산이 안 맞는다.**
`8.84` 를 `8.34` 로 잘못 읽으면 결과가 1.17 이 안 나온다.
즉 우리 쪽 오독이 문서 하나 안에서 걸러진다.

①이 사람 오타를 잡고, ②가 기계 오독을 잡는다. 둘이 역할이 다르다.
②가 있어서 헛경보가 크게 줄어든다.

## 8. 검량선은 입력 대상이 아니다

뭉치에 검량선 출력물이 여러 장 들어 있는데, 이건 **품질 기록**이다.
기기가 제대로 보정되었는지를 남기는 것이지 시스템에 입력하는 값이 아니다.

판별기가 이걸 알아보고 **넘기는 것**도 일이다.

## 9. 용어

```text
접수번호     의뢰 한 건에 붙는 번호.  모든 것의 단위
시료         검사할 물 한 병.  접수번호 하나에 여러 개가 붙는다
검체         시료와 같은 말.  시스템 화면에서 이 말을 쓴다
성적서       최종 결과 문서.  값이 반올림되어 있다
시험기록부    시스템에 입력된 원자료와 계산식이 그대로 찍힌 문서
배치         기기를 한 번 돌릴 때 함께 넣는 시료 묶음
검량선       기기가 신호를 농도로 바꾸는 기준선.  품질 기록용
표준품       농도를 아는 시료.  기기가 맞는지 확인하려고 같이 넣는다
블랭크       아무것도 없는 시료.  0 이 나와야 한다
```
