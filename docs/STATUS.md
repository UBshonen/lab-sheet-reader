# 지금 상태

2026-09-16 · **다시 개발 중.** 월별 측정망 T-N·T-P 입력 업무에 사용 요청이 생겼다.

## 이번에 붙인 것

```text
웹 화면          여러 JPG·PNG·WebP·PDF를 드래그 앤 드롭
문서 분류        결과표는 사용하고 T-N·T-P 검량선은 제외
페이지 결합      페이지 경계를 넘는 nDTNP / n 행을 시료번호로 연결
측정망 정렬      여러 측정 회차에서 1~36을 모아 번호순 정렬
하천명           하천명.jpg에서 확인한 번호별 시료명 36개
유효성 표시      값은 수정하지 않고 누락·중복·음수·DTN>TN·DTP>TP를 음영 처리
엑셀             No / 시료명 / DTN / TN / DTP / TP, 검토사항 별도 시트
```

실제 5장으로 확인했다. 결과표 3장과 검량선 2장을 정확히 나눴고,
서로 다른 두 측정 회차에서 시료 1~36을 모두 채웠다. 35번의
`DTN 4.521 > TN 3.843`은 값을 바꾸지 않고 확인 대상으로 표시됐다.

```bash
npm run dev       # http://localhost:3000
npm test
npm run typecheck
```

Cloudflare Pages 배포는 아직 하지 않았다. 현재 웹 서버의 API 부분을 Pages
Functions로 옮기고 Gemini 키를 Pages 환경변수에 넣는 작업이 남았다.

## 이전에 왜 멈췄나

만든 뒤 이 업무를 하는 분께 여쭤보니 이미 나름의 방식이 있었다.
값을 한 번 넣으면 보고서와 필요한 형태가 따라 나오게 엑셀을 짜두셨고,
무엇보다 **최초 입력이 불편으로 인식되지 않았다.**

> 한 번만 입력하면 되니까 그렇게 불편하지는 않다. 매번 하는 일이니.

기술적으로 없앨 수 있는 것과, 없애야 할 만큼 아픈 것은 다르다.
자세한 것은 [README.md](../README.md) 6절.

## 안 한 것과 그 이유

```text
화면            쓰이지 않을 것을 알고 나서 두 주를 더 쓸 이유가 없었다
시료명 매칭      자동으로 붙이면 위험하다.  유입과 유출은 한 글자 차이인데
                잘못 붙으면 값이 엉뚱한 지점에 들어가고 아무도 못 알아챈다
                사람이 한 번 확정하고 그 짝을 기억하는 구조가 맞다고 봤다
순서 재배열      시스템 화면 순서를 받아 맞추는 것.  목록을 못 구했다
```

## 남은 약점

```text
한글 시료명      숫자는 정확한데 이름이 흔들린다
                송림천 → 송립천,  백양천 → 배양4
                고정 목록이 있으면 36지선다가 되어 사라질 문제지만
                민원시료는 지점이 매번 달라 목록이 없다

                8.97 을 89.7 로 읽으면 걸리지만 8.91 로 읽으면 안 걸린다
```

## 다시 손댄다면

이 코드를 그대로 쓸 만한 곳이 있다면 이 순서가 맞다.

```text
1  그 업무를 하는 사람에게 먼저 묻는다.  만들기 전에
2  이미 어떻게 하고 있는지 옆에서 본다
3  그다음에 만든다
```

양식이 다르면 `lib/templates/` 에 JSON 하나 추가하면 된다. 코드는 안 건드린다.
판독 API 를 바꾸려면 `lib/reader/` 에 파일 하나 추가하면 된다.
