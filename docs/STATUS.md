## 무엇을 만들고 있나

시스템에 입력하기 전에, 기기 출력물을 읽어서 검증하고,
시스템에 그대로 붙여넣을 수 있는 형태로 내보내는 도구.

```text
스캔 PDF  →  판독  →  검증  →  고르고 순서 맞추기  →  복사 · 엑셀
```

배경과 원칙은 [CLAUDE.md](../CLAUDE.md), 업무 이야기는 [DOMAIN.md](DOMAIN.md).

**코드를 짜기 전에 화면 설계를 먼저 볼 것.**

## 화면 셋

```text
1  올리기          스캔 PDF + (선택) 입력 순서
2  판독 확인        문서 단위.  원본과 나란히 놓고 제대로 읽었는지
3  내보내기 정리     시료 단위.  고르고 고치고 순서 맞추고 복사
```

2와 3을 나눈 이유는 **보는 단위가 다르기 때문**이다.
판독은 문서로 보고, 내보내기는 시료로 본다.

## 먼저 재둘 것

지금 안 재두면 나중에 못 잰다.

```text
기기 출력물 한 장을 손으로 입력하는 데 걸리는 시간
한 달에 몇 건이나 하는지
최근 오타로 다시 손본 적이 있는지 · 몇 건인지
```

이 숫자가 "만들 가치가 있었는가"를 판단하는 기준선이 되고,
다른 과에 권할 때 설득 재료가 된다.

## 자료

실제 스캔본은 저장소에 올리지 않는다. `samples/` 는 `.gitignore` 대상.
시료명과 담당자명을 지운 것만 `fixtures/` 에 둔다.

**스캔본은 모아둔다.** 파서를 고칠 때마다 전부 다시 돌려보는
회귀 검사가 되고, 모델을 바꿀 때 비교 재료가 된다. 나중에는 못 만든다.
