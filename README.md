# Lab Sheet Reader

손으로 적은 시험 기록지와 시험 기기 인쇄물을 읽어서, 값이 말이 되는지
스스로 검증하고, 업무용 엑셀에 붙여넣을 형태로 내보내는 도구.

```bash
npm run read -- samples/일지.jpg     # → out/결과.xlsx
```

> **상태 — 다시 개발 중인 1차 기능.** 현재는 월별 측정망 T-N·T-P 출력물을
> 1~36번 시료로 정리하는 흐름만 웹 화면까지 연결했다. 완성 제품은 아니며,
> 다음 단계에서 다른 기기의 값도 같은 시료에 합치는 방향으로 확장한다.

---

## 무슨 문제였나

공공 시험기관에서 수질 검사 결과를 정보시스템에 등록한다.
그런데 값이 나오는 곳과 들어가는 곳 사이에 **종이가 하나 끼어 있다.**

```text
시험 기기  →  (인터넷 · USB 차단된 PC)  →  인쇄  →  사람이 보고 손으로 입력
손글씨 일지  →                                        ↑
                                            여기서만 오타가 난다
```

완벽한 디지털 데이터가 종이와 사람 손을 거쳐 다시 디지털이 된다.
이 구간을 카메라로 대신할 수 있는지 확인해보려 했다.

## 무엇을 하나

```text
스캔 · 사진
   │
   ├─ 판별      13장 중 읽을 것만 고른다. 검량선 · 공문 · 성적서는 건너뛴다
   ├─ 판독      표를 읽어 시료명과 값을 뽑는다
   ├─ 검증      정답지 없이 값이 말이 되는지 스스로 확인한다
   ↓
결과 엑셀       항목별 시트. 확인이 필요한 칸은 색으로 표시
```

## 결과

전부 실측이다. 회차별 기록은 [docs/RESULTS.md](docs/RESULTS.md).

| | |
|---|---|
| 문서 판별 | 뭉치 11장 중 **11장** 정확히 분류 |
| 기기 인쇄물 판독 | 24행 전부, 값도 전부 정확 |
| 손글씨 숫자 판독 | **138개 중 138개** (23행 × 6열) |
| 손글씨 시료명 | 42행 중 4개 오독 |
| 교차 검증 | 시험기록부와 대조해 10개 항목 전부 일치 |
| 정렬 자가검증 | 품질관리 시료 32개 모두 제자리 |
| 처리 시간 | 문서 한 장 **1분 32초** |
| 비용 | 문서 한 장 **약 17원** |

숫자는 정확하고 한글이 흔들린다. 조합형이라 자소가 뭉개지면
`송림천 → 송립천` 처럼 무너진다. 고정 목록이 있으면 사라질 문제지만,
민원시료는 지점이 매번 달라 목록이 없다.

## 한동안 왜 멈췄나

만든 뒤 이 업무를 하는 분께 여쭤봤다. 값을 한 번 넣으면 보고서와
필요한 형태가 따라 나오게 엑셀을 짜두셨다고 했다.
그리고 그다음 말이 더 정확한 이유였다.

> 한 번만 입력하면 되니까 그렇게 불편하지는 않다. 매번 하는 일이니.

자동화된 것은 **입력 이후**다. 최초 입력은 여전히 손으로 한다.
다만 그것이 매일 하는 일이라 **불편으로 인식되지 않는다.**

이 도구가 없애려던 것이 바로 그 최초 입력이었다. 기술적으로는 없앨 수
있었지만, 없애야 할 만큼 아픈 곳이 아니었다.

```text
있는 불편        ≠        느끼는 불편
```

익숙해진 불편은 불편으로 세어지지 않는다. 그래서 불편의 크기를
당사자에게 직접 물으면 과소평가된다.

**기술이 아니라 순서를 틀렸다.** 만들기 전에 물어봤어야 했다.
다만 빈손으로 묻는 것보다 돌아가는 것을 들고 간 것은 나쁘지 않았다.
물어볼 명분이 되었고, 답도 구체적으로 돌아왔다.

당시 화면을 만들지 않은 것은 의도적이었다. 이후 실제 사용 요청이 생겨
지금은 측정망 T-N·T-P 작업부터 작은 웹 화면으로 다시 시작했다.

## 실행

```bash
npm install
copy .env.example .env.local     # GEMINI_API_KEY 채우기
npm run dev                      # http://localhost:3000
npm run read -- samples/         # 폴더째 넣어도 된다
```

웹 화면에서는 JPG·PNG·WebP·PDF 여러 개를 끌어놓을 수 있다. 결과표만 읽고
검량선은 제외한 뒤, `nDTNP`와 `n` 행을 번호로 연결해 1~36 측정망 엑셀을 만든다.
여러 페이지 PDF 한 파일 안에 결과표와 검량선이 섞여 있어도 결과표 페이지만 사용한다.
판독값은 수정하지 않으며 누락·중복·`DTN > TN`·`DTP > TP` 같은 확인 항목은
화면과 엑셀의 음영으로 표시한다.

### Cloudflare Pages 배포

GitHub 연동 배포용 Pages Functions가 포함되어 있다. 저장소를 GitHub에 push한 뒤
Cloudflare 대시보드에서 두 번째 Pages 프로젝트로 연결하면 된다.

```text
Workers 및 Pages → 애플리케이션 생성 → Pages 시작 → Git에 연결

GitHub 저장소       UBshonen/lab-sheet-reader
프로젝트 이름       lab-sheet-reader
프로덕션 브랜치     main
프레임워크 사전 설정 없음(None)
빌드 명령           npm ci
빌드 출력 디렉터리  web
루트 디렉터리       비워 둠
```

첫 배포가 끝나면 `설정 → 변수 및 비밀 → 추가`에서 `GEMINI_API_KEY`를
Secret(암호화)으로 저장하고 다시 배포한다. 모델을 바꿀 때만 일반 변수
`GEMINI_MODEL`을 추가한다. 기본값은 `gemini-3.6-flash`다.

```bash
npm run pages:dev       # Cloudflare Pages 로컬 실행
npm run pages:deploy    # Git 연동 없이 Wrangler로 직접 배포할 때만
```

기관 자료를 외부 AI로 전송해도 되는지 먼저 확인해야 한다. 기본 Pages 주소는 공개되므로
실사용 전에는 Cloudflare Access 등으로 기관 사용자만 접속하게 제한하는 것이 좋다.

### 현재 범위와 다음 단계

```text
현재    자동분석기 T-N·T-P 결과표 여러 장
        → 결과표/검량선 분류
        → 측정망 1~36 결합
        → No · 시료명 · DTN · TN · DTP · TP 엑셀

다음    TOC · 현장측정기 · BOD/SS 등 다른 기기와 문서
        → 같은 시료번호·시료명으로 값 결합
        → 한 화면에서 검토하고 업무용 엑셀로 전달
```

Cloudflare Pages에서는 정적 화면을 `web/`에서 제공하고, API 키가 필요한 판독은
`functions/api/`의 Pages Functions에서 수행한다. API 키는 브라우저에 전달되지 않는다.

새 컴퓨터에서 여는 절차는 [docs/SETUP.md](docs/SETUP.md).

## 구조

```text
lib/
├── reader/          판독. 어댑터로 감싸 다른 API 로 갈아끼울 수 있다
│   ├── index.ts       공통 인터페이스
│   └── gemini.ts
├── templates/       양식 9종. 전부 JSON. 판별조건 · 열 · 지시문 · 검증규칙
├── qc.ts            품질관리 시료로 정렬 자가검증
├── rules.ts         정답지 없이 값의 타당성 검사
├── image.ts         보내기 전 이미지 축소
├── export.ts        기존 항목별 결과 엑셀
└── network-results.ts
                     측정망 1~36 결합 · 하천명 · 경고 · 엑셀

scripts/read.ts      실행 진입점
scripts/web.ts       로컬 웹 서버와 판독 API
web/                 드래그 앤 드롭 화면
functions/api/       Cloudflare Pages 판독·상태 API
wrangler.jsonc       Pages 로컬 실행·배포 설정
```

새 기기가 들어오면 `lib/templates/` 에 JSON 하나 추가하면 된다.
판독 API 를 바꾸려면 `lib/reader/` 에 파일 하나 추가하면 된다.
둘 다 나머지 코드는 건드리지 않는다.
